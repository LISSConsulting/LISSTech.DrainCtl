# CLAUDE.md

## Build
```
just all        # unsigned: CLI + DLL + PS module + MSI
just release    # signed (needs CODE_SIGNING_CERTIFICATE_THUMBPRINT in .env)
just lint       # go vet + gofmt + golangci-lint
just resource   # re-render drainctl.rc from tmpl + recompile .syso
just version    # print the version the next build will embed
```
Requires: Go 1.26+, MinGW, WiX 5, .NET SDK 8+.

## Key Rules
- Every `.go` file needs `//go:build windows`
- App version is git-derived CalVer `YY.MM.BUILD` via `scripts/version.ps1` and is injected into Go, PE resources, package naming, and the PS module. MSI `ProductVersion` is separately generated as `(100 + YY).MM.BUILD` by `scripts/msi-version.ps1`; the schema epoch prevents legacy `YY.DOY.N` installers from replacing current packages. Nothing is bumped by hand.
- The only version strings still stored in git are `docs/index.html` release-notes content, which updates manually on release refreshes (not per commit).
- Company: "LISS Consulting, Corp." (legal), "LISS Technologies" (d/b/a)
- No viper — config lives in `%ProgramData%\LISS Technologies\LISSTech DrainCtl\config.json` (encoding/json)
- Retention capped 1–365 days via `ClampRetention()`
- Branches: feature and dependency PRs → `develop` → release PR to protected `trunk`. Merge `develop`-to-`trunk` PRs with a merge commit (never rebase or squash), and immediately merge any direct `trunk` hotfix back into `develop`.
- Pre-commit: `prek` runs gofmt, go vet, golangci-lint, gitleaks
- Signing order: sign binaries → build MSI → sign MSI (`just release` handles this)

## Gotchas
- **No `structuredClone()` on Svelte 5 state** — `$state` objects are Proxies; `structuredClone()` throws. Use `JSON.parse(JSON.stringify(...))` to deep-clone reactive state.
- **Memory thresholds: Go stores % free, UI works in % used** — `api.js` `fetchSettings()`/`saveSettings()` handles the inversion. Do NOT invert a second time in components; ConfigModal, presets, and validation all operate in % used space.

## Architecture
Root package = public API. `cmd/drainctl/` = CLI (cobra). `cmd/cshared/` = DLL (P/Invoke).
Service uses `RegNotifyChangeKeyValue` + `EvtSubscribe` + poll ticker + config file watcher.
CLI/DLL try named pipe to service first, fall back to direct registry read.
Telemetry: single SQLite DB (`drainctl.db`, WAL, via `modernc.org/sqlite` — no cgo) backs both metrics and audit. Metrics flow `metrics_raw` → `metrics_5min` → `metrics_hourly` via a watermarked aggregator; retention is configurable per tier. Audit is append-only (`telemetry.AuditStore`, `PRAGMA synchronous=FULL` on a dedicated `*sql.Conn`) with one row per drain-mode transition; CLI/DLL read the same DB `?mode=ro`. Startup path: `Open → MigrateJSONL → drift reconciliation → live ingest`. `MemAuditStore` and the file-only root-package `AuditStore` were retired in feature 007.
Config: JSON file with atomic writes (named mutex + MoveFileEx). Scoped updaters for dashboard API.
Notifications: multi-target (N webhook + M ntfy), granular triggers, per-target repeat intervals.
Sessions: `WTSEnumerateSessionsW` via wtsapi32.dll, utilization alerts at configurable threshold.
Dashboard chart: LayerCake (Svelte-idiomatic composition). Session gauges per server card.
Logging: slog-based, dual-sink — ETW manifest provider "LISS Technologies-DrainCtl" (Operational channel INF+, Debug channel DBG, disabled by default) + file log (`%ProgramData%\...\drainctl.log`, rotates at local midnight to `drainctl-YYYY-MM-DD.log`, 7 days kept, local timestamps). Per-sink levels in `config.json` (`log_file_level`, `log_event_level`). CLI uses `--log-level debug|info|warn|error` flag (default `info`).
Event-log anomaly detection: `internal/evtspike` subsystem (opt-in via `evtspike.enabled`) subscribes to configured channels, maintains a robust-cap Bayesian baseline persisted to JSON, and fires `event_spike` notifications through the existing notify pipeline on confirmed spikes.

### AI anomaly investigation (feature 013)
- Deployment is central-dashboard/service only. The supported service identity is `LocalSystem`; the provider credential uses the existing atomic **machine-scope DPAPI** flow. It is write-only: never put plaintext or ciphertext in `ServiceConfig`, `DashboardConfig`, `RemoteSettings`, workers/closures/DTOs, APIs, logs, SQLite, SSE, browser state, agents, registry/environment configuration, or a user profile. `internal/investigation` alone decrypts temporary bytes for request construction after all configuration checks, then zeroes/releases them before response processing. Settings updates require exactly one credential operation: `preserve`, `replace` (provision/rotate), or `clear`.
- Provider authority is dashboard-group session only; agents and machine routes are provider-blind. Compare the extant session's login-time stored group snapshot with the atomically current `Dashboard.Group`; NEVER use a live directory-membership lookup. Apply this before feature routes and before/periodically during shared `/api/v1/events` subscription. A `Dashboard.Group` change invalidates all sessions and closes all streams; external membership changes take effect only on logout, expiry, or reauthentication.
- The sole provider profile is direct, proxy-disabled `openai_responses`: `POST https://api.openai.com/v1/responses`, fixed `gpt-6-astra`, TLS validation, redirects disabled, `Proxy:nil`. No SDK, proxy/configuration, endpoint/model override, fallback, relay, or retry. Firewall egress is TLS only to `https://api.openai.com`.
- Access and automatic investigation default false and remain separate. Enabling access accepts only `openai_responses_privacy_v1` and exactly these eight all-true booleans: `third_party_subprocessors`, `no_training_without_opt_in`, `default_abuse_monitoring_up_to_30_days`, `store_false_application_state_only`, `temporary_prompt_cache_possible`, `zdr_mam_separate_approval`, `audit_days_local_only`, and `global_endpoint_no_regional_guarantee`. Append immutable `investigation_privacy_acknowledgements` (version, authenticated actor, acceptance time, complete-clause marker/hash) first; then atomically write the exact current version and audit ID into config. Derive acknowledgement only from that matching reference. Missing/stale/mismatched/rewritten references fail closed; unreferenced rows after a config-write failure are harmless history. This ACL- and `AuditDays`-governed table is the sole actor-retaining investigation record and never egresses; safe GET returns only version and acknowledged.
- Investigation artifacts are host/customer/user/session identity-free and contain no arbitrary/nonfixed URL, raw diagnostic/event text/XML, paths, dump/file, credential, secret, or provider raw material. The only local exceptions are the acknowledgement actor and closed-provenance's fixed endpoint literal; neither egresses. Canonical host resolution is only in authorized deterministic source/list/detail; investigation SSE is source-ID-only. Model prose is escaped untrusted plain text, never Markdown/HTML/auto-link/action or remediation. Do not claim semantic validation proves absence of commands: never execute, route to tools, or derive commands, PowerShell, configuration, drains, restarts, notifications, or credential/file access from it.
- Lifecycle is one-send: queue claim sets only `running` plus `started_at_ms`; immediately before the sole `Client.Do`, atomically write `send_authorized_at_ms` and the 30-second send lease. That marker means transmission MAY have begun, not provider receipt, and forbids automatic resend. Only after local HTTP return write `send_completed_at_ms`, clear the send lease, and create the mutually exclusive fixed two-minute finalization lease. An active applicable send or finalization lease protects a running row across restart; recovery terminalizes it only after no applicable lease remains active. Same-process retry is SQLite-finalization-only. An unauthorized running row then becomes `failed/interrupted` and an authorized unterminated row becomes `failed/storage_unavailable`, with no resend or reconstruction.
- Use exact public RFC3339 lifecycle names `created_at`, `started_at`, `send_authorized_at`, `send_completed_at`, `completed_at`; internal SQLite uses `_ms`. Closed provenance uses only canonical `send_authorized_at`/`send_completed_at`, never request aliases. The only terminal reasons are `authentication_failed`, `configuration_disabled`, `configuration_invalid`, `evidence_unavailable`, `interrupted`, `network_error`, `provider_rate_limited`, `provider_request_rejected`, `provider_refused`, `redirect_refused`, `request_limit`, `response_incomplete`, `response_invalid`, `response_limit`, `storage_unavailable`, `timeout`, and `upstream_error`; provider-valid insufficiency has an empty reason.
- Enforce both caps transactionally before evidence/attempt insertion: maximum 100 queued+running attempts globally (`429 queue_full` interactively; automatic admission creates nothing), and maximum 100 retained attempts per source, including roots, retries, and local insufficiency (`409 attempt_limit_reached`).
- Session-drop remains the deterministic authority, per-host and restart-safe. The accepted-report transaction persists `servers.last_result_json` and an idempotent inbox row together. `accepted_sequence` is the sole private global order; `accepted_at_ms` is evidence/time only. Startup drains pending inbox rows strictly by sequence before newer reports, atomically applying watermark/baseline/source changes once. Public RFC3339 `confirmation_started_at` and `confirmation_ended_at` are central acceptance timestamps, not report epochs. All-hours readiness spans `first_trained_at_ms` through eligible-normal-only `last_normal_trained_at_ms`; candidates, confirms, drains, gaps, scoring, and decay do not train. Only permanent host removal clears host detector state and pending inbox rows.
