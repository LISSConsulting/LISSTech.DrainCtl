## A. Deterministic mock / SQLite / agent gate

Use a clean disposable SQLite database, fake machine auth, fixed receipt/agent clocks, fake WTS/PDH/Toolhelp/WTS-action seams, and an in-process SSE broker. Start with enabled collection, processes enabled, top-N 3, 24-hour retention, actions disabled, and all visibility modes `full`.

1. **Configuration.** Exercise top-N 0/3/5; reject -1/6; exercise retention 1/24/168 and reject 0/169; reject invalid visibility modes. Disable processes and then sessions. Change remote collector settings and collect again. Attempt every sessions-setting mutation as viewer and admin. **Expected:** valid settings atomically persist and take effect next cycle; invalid/viewer writes do not; disabled collection posts nothing; no Toolhelp work occurs when processes are disabled.
2. **Collector.** Feed service/listener/valid WTS rows, every known state and unknown numeric state, strict and malformed PDH names, missing PDH/RemoteFX, first/second process samples, inaccessible/exited processes, and deterministic top-N ties. **Expected:** service/listener excluded; unknown sorts last; only exact numeric PDH IDs attach; PDH/process failures are successful null/capability-false rows, not fatal; first CPU is null; all handles close; ordering is CPU desc/null-last, bytes desc, case-insensitive image, PID.
3. **Wire bounds.** Submit canonical decimal strings `0`, `9007199254740993`, and `18446744073709551615` for sequences/working sets; use byte values `9223372036854775807` and one greater. Submit `logical_cpu_count` 1/1024 and invalid 0/1025; CPU at `100*count` and just above. Submit valid/invalid collector versions. **Expected:** browser-facing values survive exactly; SQLite accepts only bytes through MaxInt64; CPU/count and UTF-8/control/length validations are exact.
4. **Transport.** Submit valid snapshot as `HOSTA$`, legacy 64 KiB heartbeat, anonymous/human requests, wrong-host request, malformed JSON/keys/schema/encoded body/trailing data/over-limit rows/processes, exact 512 KiB, and 512 KiB+1. **Expected:** legacy heartbeat remains independent; only machine identity succeeds; all invalid input is non-mutating; exact limit succeeds; +1 is 413 before decode.
5. **Sequence/result envelope and generation fence.** Submit same-instance newer success, equal and lower sequence, then after stopping the loop submit a lower sequence with a greater new-instance UUIDv7; submit a delayed old-instance snapshot after that commit. Inject a fatal WTS attempt and a storage failure while attempting a greater generation. **Expected:** each syntactically valid snapshot returns 202 `{accepted:true|false}`; equal/lower same-instance is accepted false and changes nothing; only the greater generation replaces and advances the durable fence; delayed lower/equal different generations are accepted false without changing the fence, rows, aggregates, or SSE; fatal preserves last success/freshness but records collection error; storage failure is 503 and rolls back, including the fence.
6. **Replacement and aggregates.** Submit two rows, then one, then a valid empty success. Recreate two rows with active, connected, idle, disconnected combinations; null/non-null projected identities; and input/connect/logon timestamps. **Expected:** replacement/clear is atomic. Persisted fleet fields equal total, active+connected, idle, disconnected, distinct non-null projected `(user,domain)` (0 when identity hidden), and max non-null activity. Inspect the fleet query plan: it uses the required fleet index and does not parse process JSON.
7. **Freshness.** With heartbeat H and last successful receipt T0, assert: no success = unknown; registry off = offline; `T0+3H` = fresh and `T0+3H+1ms` = stale; `T0+10H` = stale and `T0+10H+1ms` = offline. Submit a newer fatal error at T1. **Expected:** freshness remains based on T0, error is separate `collection_status=error`, and display precedence is offline, error, stale, fresh/unknown.
8. **Privacy and retention.** For every identity/client/process transition (including loosening), inspect SQLite before/after; then ingest the next snapshot. Advance snapshot time past retention; separately retain terminal outbox/audit and agent ledger until their action-relative acknowledgement or expiry-plus-retention cutoffs. After each privacy and retention purge, submit a delayed lower/equal generation and inspect the generation fence. **Expected:** each policy change immediately purges dashboard snapshots/latest and cancels/expires applicable actions; hidden identity gives user count 0 and hidden processes give `[]`; raw data never persists or returns; snapshot deletion is not coupled to terminal action/audit/ledger deletion; the generation fence remains and rejects delayed old generations.
9. **Migration/composition.** Upgrade supported prior database, rerun migration, create service composition root, ingest/action/report, stop, restart. **Expected:** dashboard has exactly `session_generation_fence`, `session_snapshots`, `session_latest`, `session_action_outbox`, `session_action_audit`; agent has separate `session_action_ledger`; all six tables and required indexes are transactional/idempotent; stores are injected through `NewSubsystem`, lifecycle-safe, and durable across restart. Confirm the persisted fence still rejects a lower/equal delayed generation after restart.
10. **Read/SSE.** As admin/viewer query `/api/v1/me`, list/detail/actions/status. Subscribe both to SSE, commit success then fatal error. **Expected:** viewer is 403 before query/mutation; fleet contains only aggregate metadata; detail is <=500 projected rows/no-store; `session_snapshot` is metadata-only and viewer ignores it; no event exposes PII, logon time, action ID, or message.
11. **Actions and ledger.** With actions disabled, POST actions; then enable and submit disconnect/logoff/message. Test body unknown key, disconnect/logoff nonempty message, message empty/missing message, idempotency replay/conflict, 21 deliveries, redelivery, expiry, session-ID reuse, protected message deletion, and restart after durable claim but before WTS completion. **Expected:** disabled route exists and returns `409 sessions_disabled`; disconnect/logoff bodies allow only empty/omitted message; message requires nonempty message; message plaintext is protected and erased at terminal state; disconnect carries no message fields and invokes `WTSDisconnectSession(..., false)` only after durable claim and exact logon guard.
12. **Action realtime recovery.** Queue an action, capture `session_action` status SSE, reload the frontend fixture, and advance fake time in 2-second increments. Navigate away before terminal once; repeat through terminal. **Expected:** event contains only safe ID/lifecycle/outcome/timestamps; pending ID survives in sessionStorage; GET status polls every 2 seconds, stops on navigation/terminal, resumes after reload, and terminal maps to an accessible safe toast.

## B. Production build and deterministic browser-driver smoke

Run the production frontend build and start the built dashboard against the deterministic fixture from A. Use a browser-driver session, not a nonexistent checked-in browser test command.

1. Open a fresh tab as `viewer`; navigate to `/`; inspect visible navigation and request log; then directly navigate to `/sessions`. **Expected:** no Sessions navigation, no session API request, and 403/blocked route.
2. Open a fresh tab as `admin`; navigate to `/sessions`; wait for fleet list. **Expected:** primary Sessions navigation, summary-only rows, result count, and no username/client/process/PID/message text in DOM, ARIA, title, or network list response.
3. Type a host query; select freshness/capability filters; sort twice; change page; narrow viewport; use keyboard through controls. **Expected:** deterministic filtered/sorted page, accessible horizontal table, visible focus and correct ARIA state.
4. Expand `hosta.example.test`; wait for detail GET; emit a newer `session_snapshot`; inspect network; emit a newer fatal error. **Expected:** SSE never supplies expanded data; expanded host refetches once; stale response cannot overwrite newer sequence; fatal error does not clear prior detail.
5. Set all modes masked then hidden through admin settings; refresh and inspect DOM, ARIA, titles, network bodies, SSE frames, errors, and audit fixture. **Expected:** masked deterministic values only; hidden identity/client has no recoverable value, hidden process list is empty, and no raw value is present.
6. Enable actions. Open then Escape/cancel confirmation; reopen and confirm a disposable action. **Expected:** dialog names host/numeric ID/logon/action, focus traps/restores, cancel has no request, confirm sends one request, and pending safe toast appears.
7. Emit pending then terminal `session_action` SSE; reload during pending; wait 2 seconds; navigate away in one trial and remain in another. **Expected:** pending tracking restores from sessionStorage, status GET is every 2 seconds, navigation aborts it, terminal stops it and announces safe outcome.
8. Activate Shadow for a disposable session. **Expected:** the endpoint returns `drainctl-shadow://shadow?host=hosta.example.test&session=42`; the browser performs the normal external-protocol flow and does not auto-launch during fixture/test loading. The adjacent Copy fallback copies exactly `mstsc.exe /v:hosta.example.test /shadow:42 /control`; neither path adds `/noConsentPrompt`.

Record browser build hash, fixture clock, each URL/action, observed request/event payload class (never sensitive payload), screenshots/DOM assertions, and pass/fail.

## C. Windows RDS Session Host gate

Use non-production Windows Server/RDS with disposable active and disconnected RDP sessions and a reachable test dashboard.

1. Start agent/default settings; compare sessions to `query user`/`qwinsta`. **Expected:** exact numeric IDs/logon times/WTS state, no service/listener rows, current metrics and bounded deterministic processes.
2. Block reporting through freshness thresholds then restore it. **Expected:** exact fresh/stale/offline transitions from last successful receipt and recovery without losing last good data.
3. Restart agent only after its reporting loop stops. **Expected:** new instance generation accepted; same-instance duplicate sequence does not replace data.
4. Repeat visibility purge/full-after-purge checks using disposable identities. **Expected:** dashboard/API/storage immediately remove old detail and never restore pre-purge raw data.
5. Against only disposable sessions, test disabled action, confirmation/cancel, guarded disconnect, guarded logoff, guarded message, session ID reuse seam, valid Shadow launch URI, malformed Shadow URI rejection, and command copy fallback. **Expected:** no dashboard-side WTS/mstsc; the local helper receives only strict URI input and starts mstsc only after browser/Windows protocol confirmation; the agent performs at most one guarded local WTS call; message text never reaches dashboard audit/SSE/logs; disconnect never carries message text.
6. Repeat keyboard/accessibility flow from B at narrow viewport. **Expected:** all controls usable and announcement/focus behavior correct.
