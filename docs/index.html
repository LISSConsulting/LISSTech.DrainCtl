Architecture
Three signals. One answer.
The service triangulates registry notifications, event log subscriptions, and safety-net polling to deliver a definitive, attributed state.

Registry Notification

Windows fires RegNotifyChangeKeyValue the instant TSServerDrainMode is written. Zero delay.

~0ms

Event Log Subscription

EvtSubscribe on Security Event 4657 pushes the username, domain, and process that made the change.

~200ms

State Evaluation

The service reads the registry, detects transitions, correlates attribution, evaluates the grace period, and appends to the audit store.

in-memory

Instant Query

CLI and PowerShell connect via named pipe. No file I/O, no registry reads. The answer is already computed.

\\.\pipe\drainctl

Farm Monitoring
One dashboard for your entire RDSH farm.
See every server's drain state, session count, and alert history on a single page. Enable the dashboard on one server, point the others at it, and you're done.

📗 Quick Setup

Enable the dashboard, register your servers, and open the URL. That's it — no IIS, no database, no config files to hand-edit.

# On the dashboard server: drainctl dashboard enable Restart-Service DrainCtl # On each RDSH host: drainctl register https://dashboard:49470
  • Health, grace, and alert status at a glance
  • Session utilization gauges per server
  • State history chart over time
  • Live event log of every transition
  • Notification settings right in the UI

🔒 Secure by Default

Uses your existing Active Directory — no extra passwords, no separate login page. Open the dashboard, and Windows handles the rest.

  • Kerberos single sign-on (SSO)
  • Restrict access to any AD group
  • Agents authenticate automatically
  • No credentials stored anywhere

Default access group: Domain Admins. Change it in the config or with drainctl dashboard enable --group "RDS Admins"
