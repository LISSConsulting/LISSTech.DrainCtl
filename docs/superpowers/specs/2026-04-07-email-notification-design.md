# Email Notification Target (SMTP)

**Date:** 2026-04-07
**Status:** Approved

## Problem

DrainCtl supports webhook and ntfy notifications but not email. Many ops teams rely on email for alerting. Users want to send notifications via any SMTP relay (including Mailgun, SendGrid, O365 via SMTP credentials).

## Solution

Add an `"email"` notification target type that sends HTML emails via SMTP (AUTH LOGIN/PLAIN with STARTTLS or implicit TLS). No external dependencies — uses Go's `net/smtp`.

---

## 1. Config

New `"email"` target in the `notifications` array:

```json
{
  "type": "email",
  "url": "smtp://mail.example.com:587",
  "to": ["ops@example.com", "oncall@example.com"],
  "from": "drainctl@example.com",
  "secret": "smtp-password",
  "triggers": ["drain_on", "drain_off", "alert"],
  "repeat_minutes": 30
}
```

- `url`: `smtp://host:port` (STARTTLS) or `smtps://host:port` (implicit TLS on connect)
- `to`: string array, at least one recipient required
- `from`: sender address, required
- `secret`: SMTP password for AUTH PLAIN/LOGIN
- `triggers`, `repeat_minutes`: same semantics as webhook/ntfy

## 2. NotificationTarget Changes

Add two fields to the existing struct:

```go
To   []string `json:"to,omitempty"`
From string   `json:"from,omitempty"`
```

Only used when `Type == "email"`. Ignored by webhook/ntfy.

## 3. SMTP Client

New file `email.go` in the root package.

**Connection flow:**
1. Parse URL scheme and host
2. `smtp://` — dial TCP, issue EHLO, STARTTLS upgrade, then AUTH PLAIN
3. `smtps://` — dial with `tls.Dial` (implicit TLS), EHLO, AUTH PLAIN
4. Set envelope (MAIL FROM, RCPT TO for each recipient)
5. Write MIME headers + HTML body
6. QUIT

**Timeout:** 15 seconds for the entire send operation.

**No external dependencies.** Uses `net/smtp`, `crypto/tls`, `net`.

## 4. Notification Subjects (all target types)

Natural language subjects per trigger, used across **email, webhook, and ntfy**:

| Trigger | Subject |
|---------|---------|
| drain_on | `RDS01 — New remote connections disabled by DOMAIN\admin` |
| drain_off | `RDS01 — Remote connections re-enabled by DOMAIN\admin` |
| alert | `RDS01 — Remote connections disabled for 2h 15m (exceeds 1h grace period)` |
| grace_entered | `RDS01 — Remote connections disabled, 45m remaining in grace period` |
| healthy | `RDS01 — Remote connections enabled, server healthy` |
| session_warning | `RDS01 — Session utilization at 85% (17/20 sessions)` |

Generated by a shared `NotificationSubject(result, trigger, changedBy)` function in `notify.go`. Used by:
- **Email**: MIME `Subject` header
- **ntfy**: `Title` header (replaces current short title)
- **Webhook**: `subject` field in JSON payload (new field, existing fields unchanged)

## 5. HTML Template

Embedded via `//go:embed email_template.html` in the root package.

**Design principles** (matching dashboard/landing/guide):
- Rose gold accent bar on the left edge of the card
- System font stack: Segoe UI, -apple-system, sans-serif
- All styles inline (email clients strip `<style>` blocks)
- Card layout on white background
- Status badge: green (Healthy), amber (Grace), red (Alert), gray (Offline)
- Fields: Server, Mode, Status, Duration, Changed By, Timestamp
- Footer: "Sent by LISSTech DrainCtl — LISS Technologies"
- Tested against: Outlook, Gmail, Apple Mail rendering constraints

**Rendered via `html/template`** with a `emailData` struct containing all template fields.

## 6. Integration

In `notify.go`, `SendNotification` already switches on `target.Type`. Add:

```go
case "email":
    sendEmail(target, result, trigger, changedBy, log)
```

Same retry/cooldown logic applies (repeat_minutes, per-target state).

## 7. Validation

`Config.Validate()` checks for `"email"` targets:
- `url` must start with `smtp://` or `smtps://`
- `to` must have at least one non-empty address
- `from` must be non-empty

Invalid email targets are logged as warnings and skipped (same as invalid webhook URLs).

## 8. Testing

- **SMTP send**: unit test with a local TCP listener that speaks enough SMTP to accept a message, verify headers/body
- **Template rendering**: render with a sample CheckResult, verify HTML contains expected fields (server name, status, duration)
- **Subject generation**: test each trigger produces the expected subject line
- **Config validation**: missing to/from/url rejected with warning

## Non-Goals

- No HTTP API transports (Mailgun API, SendGrid API, SES API) — SMTP covers all of them
- No plain-text fallback — HTML only (all modern email clients render it)
- No attachments
- No customizable templates (embedded default only)
