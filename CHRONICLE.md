# CHRONICLE

Cumulative changelog for DrainCtl (Roams #1-99).

## Bug Fixes

- `ServerView` (Go) was missing `state_changed_at` — `ServerDetail.svelte` and `ServerTable.svelte` both read `server.state_changed_at` to display the "State Since" tile row and the state-age column respectively, but the field was never emitted by the real backend; in production the detail tile always showed `'—'` and the table column silently fell back to `registered_at` (the server's registration time, not the current-state onset); fixed by adding `StateChangedAt *time.Time json:"state_changed_at,omitempty"` to `ServerView` and assigning `r.StateSince` in `toServerView()`; the mock-api already emitted this field correctly; `api.js` typedef and `openapi.yaml` schema updated to document the field; `ServerDetail.svelte` `stateSinceStr` also replaced `toISOString()` (always UTC) with `formatTs()` for locale-aware local time, matching the format used everywhere else in the dashboard
- `HistoryModal.svelte` `loadHistory()` had a stale-result race — toggling "Transitions Only" while a previous fetch was in flight started a second async call concurrently; whichever finished last overwrote the result, so the data could reflect the wrong filter value; fixed with a `fetchSeq` integer counter: each call captures `mySeq = ++fetchSeq` and only writes to state if `mySeq === fetchSeq` at resolution time, ensuring superseded in-flight calls are silently discarded

- `ServerTable.svelte` was missing `.filter-pill.warning.active` CSS — the "Warning" filter pill fell back to the generic dark active style instead of amber, inconsistent with every other status pill and badge in the dashboard (dot, pill, StateBar segment, CounterGrid card, and HistoryModal badge all use `var(--color-amber)` for `warning`); added the missing rule matching the `.filter-pill.grace.active` pattern; `removeErrorTimer` was a plain `let` with no cleanup — if the component was destroyed while a remove was in flight the 5-second auto-dismiss timer could fire on an unmounted instance; wrapped in an `$effect(() => () => clearTimeout(removeErrorTimer))` to guarantee cleanup on destroy; `aria-label="Filter servers by hostname"` added to the hostname search input which previously had only a `placeholder` attribute, making it inaccessible to screen readers that skip unlabeled inputs
- `Nav.svelte` tab buttons had `role="tab"` without a parent `role="tablist"`, an ARIA validity violation — wrapped the `{#each TABS}` block in `<div role="tablist" aria-label="Dashboard views">` with `display:contents` so layout is unchanged; all three view-switching buttons are now part of a valid ARIA tab widget

- `Footer.svelte` / `App.svelte`: the "Refresh now" button gave no visual feedback during a fetch — `refreshing` was a plain `let` variable in `App.svelte` (not reactive `$state`), so Footer could not observe it; promoted to `$state(false)` and passed as a new `refreshing` prop; Footer now sets `aria-busy` and `disabled` on the button while a refresh is in flight and wraps the `RefreshCw` icon in a `<span class="spin">` that plays a 0.7s CSS keyframe rotation; `disabled` styling uses `opacity: 0.5` and `cursor: not-allowed`; `App.svelte` SSE `onmessage` catch block now logs `console.warn('[SSE] malformed event, ignored:', e)` instead of silently discarding parse errors, making debugging unexpected payload shapes possible without polluting the event log

- `ServerTable.svelte` CPU cell used `srv.perf.cpu_pct.toFixed(1)` — crashes with `TypeError` if `cpu_pct` is absent from the perf snapshot (e.g., a backend field temporarily missing during a rolling deploy); changed to `srv.perf?.cpu_pct != null ? ... : '—'` guard; Input Delay cell rendered `'—ms'` when the field was null because the `'ms'` suffix was unconditionally appended regardless of whether a value was present — changed to append the unit only when a measurement exists; `removeServer()` error handler used `e.message` which is `undefined` when the thrown value is not an `Error` instance (e.g., a plain string from a network failure); fixed to `e?.message ?? String(e)`
- `EventLog.svelte` lacked a CSS rule for `.det-badge.state-warning` — a server-update event with `drain_state='warning'` rendered the drain-state badge completely unstyled (no background, default text color) instead of amber, inconsistent with every other state badge; added the missing amber rule matching the `state-grace` convention; fleet-metric display values in the periodic-refresh branch were rendered without `.toFixed()` calls (e.g., `{evt.fleet_cpu_pct}%` instead of `{evt.fleet_cpu_pct.toFixed(1)}%`), inconsistent with per-server metric formatting — all six fleet metric values now use `.toFixed(1)` or `.toFixed(2)` to match the precision used in the per-server event detail rows

## Bug Fixes

- `Footer.svelte` now shows a pulsing amber RECONNECTING state when the SSE `EventSource` is in CONNECTING state after a transient error — previously the footer showed "CONNECTED" (same as polling-only mode) during SSE reconnect attempts, giving operators no indication that live updates were temporarily unavailable; `App.svelte` SSE `onerror` handler now checks `es.readyState === EventSource.CONNECTING` to distinguish transient drops (set `sseReconnecting = true`) from permanent closure (set `sseReconnecting = false`, close and re-check session); `onopen` clears `sseReconnecting`; `state.svelte.js` exposes `sseReconnecting` as a reactive getter/setter alongside `sseConnected`
- `ServerTable.svelte` `doRemoveServer()` `setTimeout` for clearing `removeError` was untracked — if a second remove operation failed before the first 5-second timer fired, the earlier timer would clear the newer error message prematurely; fixed by storing the timer ID in `removeErrorTimer` and calling `clearTimeout(removeErrorTimer)` before each new `setTimeout`
- `ServerTable.svelte` `sortDir` and `pageSize` were initialised with `parseInt(localStorage.getItem(...) || '1', 10)` — if stored values were corrupted (e.g. `"NaN"` or non-numeric strings), `parseInt` returns `NaN` and the `||` fallback never fires; NaN `sortDir` makes all comparison results `NaN` (treated as 0 by sort), silently breaking column sort; fixed by adding `|| 1` / `|| 15` after the `parseInt` call so invalid stored values always fall back to safe defaults
- `Toast.svelte` copy button lacked `aria-label` — screen readers would announce "Copy" (button text) without context; added `aria-label="Copy message"` so the purpose is unambiguous

- `App.svelte` SSE `server_update` handler now detects status transitions immediately and emits event-log entries in real time — previously the event log lagged up to 30 seconds behind visual state changes because transition detection only ran in the polling `refresh()` cycle; `prevStates` is also updated on each SSE event so the subsequent poll cycle does not duplicate the same transition entry
- `App.svelte` SSE `settings_update` handler now applies the same memory-threshold inversion (`mem_warn_pct = 100 - raw`) that `fetchSettings()` applies on REST load; previously the raw Go "% free" value was stored directly in `appState.config`, causing threshold gauges to display incorrect colors until the next manual page refresh after any in-session settings change

- `frontend/dev/mock-api.js` had no handler for `GET /api/v1/events` — the Vite middleware returned `null` → Vite served a 404 → EventSource retried the SSE connection forever in dev mode, causing the footer to always show "CONNECTED" instead of "LIVE"; fixed by adding a proper streaming SSE handler in `configureServer` that sets `text/event-stream` headers, tracks active connections in an `sseClients` Set, sends 25-second keepalive comments, cleans up on disconnect, broadcasts `server_update` events when `startEvolution()` fires a status transition, and broadcasts `settings_update` when `PUT /api/v1/settings` is called
- `internal/dashboard/server_test.go` had no HTTP-level test for `handleSSE` — only the broker itself was covered; added `TestHandleSSE_DeliversBroadcastedEvent` (verifies `Content-Type: text/event-stream` header and `data:` frame delivery after a broker broadcast) and `TestHandleSSE_TooManySubscribers` (verifies 429 when the subscriber cap is reached)
